# 11 — 通过仓库分发执行多个可交付单元

**What to build:** 让既有仓库分发入口作为兼容 adapter，通过 deep 仓库分发 module 按确定顺序执行多个可交付单元，隔离单元失败并生成完整分发结果。

**Blocked by:** 08 — 落实执行取代与工作区初始化规则; 10 — 让分发预检运行复用完整交付预检.

**Status:** ready-for-agent

- [ ] 每份递归匹配的仓库交付配置形成独立可交付单元。
- [ ] 可交付单元按源码仓库名称和配置相对路径形成确定性分发顺序。
- [ ] 每份配置只读取一次，通过预检后固定用于本轮单元执行。
- [ ] 配置发现引用的最新读取语义与已解析配置版本被记录，不错误冻结仓库级配置快照。
- [ ] 每个单元开始前和结束后执行规定的工作区隔离与清理。
- [ ] 单元被拒绝或执行失败后继续处理其他单元，已成功交付不回滚。
- [ ] 分发明细记录成功、跳过、撤回、被拒绝和执行失败，汇总数量准确。
- [ ] 配置要求末尾失败且存在拒绝或失败时，最终 Jenkins Job 结果为失败。
- [ ] 既有 `dispatchCodeupRepositories` 调用方式和合法旧配置继续通过兼容基线。
